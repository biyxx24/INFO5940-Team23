## 1. Problem and rationale for using LLMs

**Problem.** Research assistants and junior analysts often have to answer one specific question from a company's annual report (Form 10-K), such as "Why did gross margin fall this year?". A 10-K runs over 100 pages, and the answer is split up: the figure is in the financial statements, the explanation is in the management discussion, and the detail is in a note. Comparing years means repeating the search in each year's report. Doing this by hand is slow, and it is easy to miss the right paragraph, mix up years, miscalculate a figure or other problems.

**Why an LLM.** ReportTrace is a local web where the user selects a company and one or more fiscal years, then asks a chatbot any question about those reports. The hard part of this task is language, which is what an LLM is good at: it understands an open question, finds the relevant passages even when the report uses different words to descript one thing, and turns long passages into a short answer.

## 2. Planned LLM integration

The chatbot combines retrieval-augmented generation (RAG) with an agent. For RAG, each report is split into passages, embedded, and stored in a local Chroma vector database with its company, year, and section, so the chatbot answers from retrieved text and not from the model's memory.

On top of this, one LLM agent handles everything the user asks: single-year questions, year comparisons, and questions the reports cannot answer, such as "Should I buy this stock?". The agent is built with LangChain. It plans what evidence a question needs and chooses among four tools: `search_report` finds passages by meaning in one selected year, `read_section` opens a whole section, `find_financial_data` returns the figures the company filed with the SEC, and `calculate` does the arithmetic in Python. If the evidence is not enough, the agent searches again, up to 10 tool calls per question.

Two things go beyond a normal "chat with your PDF" tool. First, when the user selects several years, the agent searches each year separately and lines up the results, so the answer shows what changed between years. Second, before an answer is shown, a code checker confirms that every quote appears word for word in a retrieved passage and that every number comes from a tool. Anything else is removed and listed as "not found in the reports". The model is **OpenAI GPT-4o**, through the API that Cornell provides to students, with `text-embedding-3-small` for embeddings.

## 3. Project scope and feasibility

ReportTrace will be a local Streamlit web app with the five features in the table below. This is a meaningful project because it combines a data pipeline, RAG, an agent with tools, a checker, and a two-panel interface, and we will measure its accuracy with at least 30 test questions. It is achievable in the three weeks of Construction because all the data is public and free from one source, there is one agent, and everything runs locally. Out of scope for the MVP: comparing different companies, uploading PDFs, filings other than the 10-K, non-U.S. reports, investment advice, stock prices and news, user accounts, and cloud deployment.

| Feature                   | What it does                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Report library**  | Stores the annual reports of at least 10 U.S.-listed companies, 3 fiscal years each. A script downloads them from the SEC and prepares them for search. |
| **Selection panel** | The user picks a company and ticks one year, or several years to compare. The chatbot only uses the selected reports.                                   |
| **Chatbot**         | Sits beside the selection panel. The user asks any question and sees the agent's steps while it works.                                                  |
| **Year comparison** | With several years ticked, the answer shows the years side by side: what changed and what stayed the same.                                              |
| **Evidence cards**  | Every statement links to the quoted passage, its year and section, and the filing. Missing information is listed, not guessed.                          |
